# Reader consequences

The Reader projects delivered `storyMutation` events into gain cards and relationship confirmations. The engine owns every gain, cost, request unlock, and checkpoint; this UI never grants rewards. Simultaneous attribute and favor changes remain visible together. Received items show the actual localized name and signed quantity, and a request unlock announces its authored name. A changed favor tier earned during a scene queues its own confirmation after that scene's final dialogue and end actions have completed. Its character portrait, tier, and source skill description describe the actual earned change. Favor, unlocks, and conditions change at their original action; only the tier announcement waits. Letter and relationship confirmations follow their source stage sequence and block Reader input synchronously while visible.

The same consequence projection appears inside an active native journey dialog, including shops, gifts, events, and prize draws. The outside stage cards are suppressed while that dialog contains them, so there is one live receipt region. Dialog receipts stay visible while its contents scroll. Planning-page notices use a viewport layer outside the stage's CSS containment, so scrolling to a calendar action cannot hide a new request or gain. Opening or closing a dialog relocates the notice; it cannot deliver a mutation or acknowledge a reward. The journey overview uses source labels with readable fallbacks and formats player-name/markup placeholders through the existing English parser. Scratch tickets conceal their unselected source rewards and offer a separate Receive prizes action. A complete journey offers Continue to a new cycle only when its authored terminal allows it.

`ReaderPresentations` deduplicates by run and event sequence and preserves distinct authored repeated rewards. Attachment can project existing ordinary receipts, but historical tier mutations and loaded favor levels never announce a newly earned relationship. Zero gains and unchanged tiers create no notice. Gain cards expire after six seconds of the presentation clock; this duration is a Reader convention. Confirming a tier only dismisses its notice and resumes the next queued journey task. It cannot reapply the tier or its unlock rewards. Opening History, rerendering, or subscribing cannot deliver a gameplay action. A checkpoint restore/new run clears notices and cancels their timers; stale events and confirmations are rejected. Scene transitions keep the playthrough's run ID and live ordinary notices; pending tier notices belong to their qualifying scene. Route flags, conditions, ending IDs, and Developer diagnostics never become gain cards.

Scene handoffs clear outgoing stage actor membership and fading tracks while retaining accumulated `StoryState`. The visual stage is keyed by run and scene identity, disposing outgoing Spine instances and pending asset callbacks at that same boundary. Dialogue nodes within a scene keep their actors and intentional compositions.
